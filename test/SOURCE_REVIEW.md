# WSL Kali 源码审阅与回归说明

本轮以 `01ce7933b4e60cd32d95af0c358ea69c8af36557` 后的源码树为输入，目标是
在 WSL Kali 的 x86-64 CPU 上编译和运行。原始清单包含 881 个源码、头文件、
汇编、维护源和构建脚本，共 593,548 行；清单保存在
[`source-review-inventory.csv`](source-review-inventory.csv)。这些数字描述
审阅开始时的文件，不包含本轮新增测试，也不把对象文件、二进制和生成的 PTX
算作需要手工修改的源码。

## 阅读范围

| 范围 | 阅读和核对方式 |
| --- | --- |
| `top/`、根目录 `demo.c`、现代 `Makefile`、原有 `test/` | 按函数阅读参数、表达式、输入输出、对象生命周期、构建依赖与测试判定；核对错误返回和实际调用方。 |
| `include/`、`ms_include/` | 阅读声明和内联实现，检查类型宽度、数组容量、条件编译以及与调用方的一致性。 |
| `arith/`、`aprcl/`、`mulmod128/`、`ysieve/`、`ytools/`、ECM 与其余分解入口 | 阅读算术、筛选边界、队列、线程池、资源释放和素性判断；不同 limb/ISA 实现分别对照。 |
| `factor/qs/`、`common/`、`mpqs/` | 阅读筛选、关系解析和存储、图构造、线性代数、平方根和演示入口；展开的指令集实现按算法族核对控制流、边界和差异。 |

| `factor/nfs/`、`gnfs/` | 阅读作业恢复、关系文件、线程状态、外部进程和多项式流程；旧 `poly_brb_mod` 分支按相同副本与分叉实现分别核对。 |

| 旧 `Makefile.gcc`、`.clang`、`.icc` 和配置示例 | 阅读编译器选择、依赖路径、CPU 选项、对象和链接规则；本机 `config.mk` 只用于核对实际配置。 |

Jacobi 等大段生成常量按生成来源、声明尺寸及消费索引核对，没有人工重算每个
数学常量。重复副本采用内容比对与差异阅读；这不等同于对全部汇编指令、第三方
数值算法或所有输入进行形式化证明。

## 主要修复

- 命令行和 INI 严格检查数字范围、缺值和长度；显式表达式在管道环境下仍会执行。
  长表达式、无末尾换行、脚本重复、批处理替换和失败时保留原输入均有回归。
  调优记录同时支持含六个和九个数值字段的格式，拒绝不完整或非有限数值记录。
- 计算器检查函数参数和数值定义域，正确处理变量、输入进制、语句错误传播、
  `sigma`、`totient` 及空素数区间。`fftmul` 原入口实际执行内部计时实验，
  不保证普通乘法语义，现在明确拒绝并提示使用 `a*b`；实验实现仍留在算术源码中。
- 修正小区间筛选的上下界、种子素数补回、PRP 结果压缩、单块偏移和输出容量。
- 修正 64/128 位 GCD、52 位借位及乘法辅助常量、104 位约简比较和有符号 GMP
  转换；APR-CL 使用独立线程工作变量，避免大参数溢出和数组末端多读。
- 52 位 Miller–Rabin 接口执行真正的强测试；104 位 Lucas/Selfridge 返回实际
  判断结果；修正 Jacobi 零余数死循环、非 IFMA 配置下的 Fermat 误判和向量移位进位。
- 修正线程池初始化失败与关停资源处理、任意长度/未对齐排序、扩容后的旧指针、
  关系因子容量和 small MPQS 的结果数组及清理。
- 修正 NFS 文件拆分丢尾行、损坏恢复文件、缺失字段、关系解析、未初始化参数、
  外部命令失败处理及 lasieve 批量因子树扩容后的旧指针。
- 静态库由唯一规则构建；编译选项变化会更新依赖记录；测试对象跟踪头文件；
  Linux CI 的回归失败会令任务失败。
- 修正调优数据的未初始化值、检查点和 NFS 路径容量；`make lasieve` 将本地
  筛选器写入 `factor/lasieve5_64/bin/local/`，`yafu.ini` 使用相同目录。

## 可复现检查

现有 GCC、make、GMP、GMP-ECM 和系统 zlib 足够运行 CPU 检查，不需要安装新的
软件。以下命令在仓库根目录顺序运行：

```sh
make -j4 all test-full
make -j4 lasieve
./yafu_test_full --tag fast
sh test/test_cli.sh ./yafu
make test-standalone
./yafu_test_full modular sieve
./yafu_test_full siqs --tag siqs-c50
make -j4 test-sanitize
make -j4 yafu test-full FORCE_GENERIC=1 ECM=0
./yafu_test_full --tag fast
make -j4 yafu test-full USE_NATIVE=0 USE_AVX512=1 USE_AVX512IFMA=0
./yafu_test_full --tag fast
make -j4 all test-full
```

SIQS 会在当前目录写保存文件；需要隔离时，从临时工作目录用绝对路径调用
`yafu_test_full`。较大的 SIQS 和大量 ECM 用例应按需要单独运行。

| 常规及 ASan/UBSan 构建的真实命令行入口 | 43 项检查通过，包含新旧调优格式。 |
| 同一构建的 SIQS 50 位整数分解 | 得到 25 位和 26 位因子，6 次检查通过。 |

不等同于重新推导全部常量。

## 证据边界

实际运行验证针对 WSL Kali CPU。CUDA、OpenCL、Windows 和 Intel 编译器分支
只有源码检查或局部编译证据；没有把这些分支写成已在目标设备运行。未执行完整
GNFS/CADO 长作业，也没有运行全部大规模因数分解和性能用例。第三方旧快照未
在本轮整体升级。

52 位 MR 和 104 位 Lucas/Selfridge 的部分接口当前逐通道调用标量实现，优先
保证结果正确，可能比完整向量实现慢。未接入当前构建的旧 `tfm.h` 仍引用仓库中
缺失的历史 `z` 类型；没有猜测恢复这套接口。构建仍有旧代码的转换和未使用项
警告，不能将编译成功理解为警告已全部消除。

NFS 的部分外部程序仍通过 shell 启动；已有配置路径应避免 shell 元字符。
`siqsSSalloc=15` 仍可能请求约 8 GiB 的单向 slice，这是该参数的资源含义。
源码审阅和有限回归不能保证任意输入、任意平台均无缺陷。
